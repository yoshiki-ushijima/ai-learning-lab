業務の流れ

  1. ログインIDとパスワードを入力する。
  2. 認証を実行する。
  3. 認証成功後、日報検索のカレンダー・一覧を表示する。
  4. 利用終了時はログアウトする。

分岐・例外

  • 入力不足・形式不正・認証失敗ではログイン画面に留まり、エラーを表示する。
  • セッション切れでは保護された画面・APIを利用できない。

表示の共通ルール

全画面のI/O区分・表示形式・揃え方・未設定値・長文の扱いは画面表示共通ルールに従う。各画面の項目表でI/O・表示方式・揃え方を指定する。

S-001 ログイン画面仕様

S-001 ログイン画面

目的

利用者がログインし、ロールに応じた初期画面へ遷移する。

主要項目

区分項目I/O表示方式揃え方
項目ログインIDI文字列をそのまま表示左詰め
項目パスワードI伏せ字。表示操作時は入力値をそのまま表示左詰め
項目エラーメッセージOメッセージ全文を折り返して表示左詰め

遷移

  • ログイン成功時は日報カレンダー・一覧画面へ遷移する
  • ログイン失敗時はログイン画面に留まり、エラーを表示する

利用者情報の最新化と認証監視

  • ログイン中利用者の取得では、要求のたびに登録された最新の利用者情報を再取得する。ログイン時の保持情報をそのまま返す方式にはしない。
  • 認証監視で、表示中の利用者と最新の利用者のユーザーIDまたはロールが異なることを検知した場合は、現在画面と未保存入力を破棄し、最新の利用者の日報カレンダー・一覧画面（S-002）へ戻る。別タブで別アカウントへ再ログインした場合も同じ扱いとする。
  • ユーザーIDとロールが同じ場合は、最新の利用者情報を受け取り、現在画面と未保存入力を維持する。通信失敗と認証失効は区別する。

取得・失敗時処理、監視とログアウトの競合、期限の技術条件は認証・セッション方式とログイン詳細設計で具体化する。

ログインパネルの見た目

ログインパネルは初期表示・ID入力エラー・認証失敗のモックに合わせる。見出し背景、案内位置、必須ラベル、表示切替ボタンとログインボタンの配置・サイズを基準にする。初期ユーザー例やモック説明は設計注釈であり実画面の項目ではない。

画像比較はパネルの寸法を保持して同じ撮影原点・背景へ固定し、同一環境で画素差0を判定する。自然配置の幅・拡大・操作性は別の画面テストで確認する。

合意済みの操作・復旧条件

Enterで送信でき、Tabで全操作部品へ到達しフォーカスが見える。失敗時はIDを保持しPWを消去する。入力で該当エラーを非表示にし、送信中は重複送信できない。幅360/768/1280pxと200%拡大で切れ・重なりを起こさない。

通信失敗・不正な成功応答ではログイン画面に留まり、安全な案内を表示し再入力・再送で復旧できる。同一/別アカウントへの正しい再ログインは新しい認証として成功し旧CSRFは無効になる。ログアウト後の戻る・再読込では保護画面を再表示しない。

APIの確定文言はAPI一覧に従いそのまま表示する。

目次ログイン入力許可文字・禁止文字チェック時の扱い

ログイン入力

項目チェックエラー時
ログインID必須、最大80文字、許可文字のみで構成する項目に入力エラーを表示する
パスワード必須、最大72文字、禁止文字を含まない項目に入力エラーを表示する

許可文字・禁止文字

項目許可文字禁止文字入力例
ログインID半角英字 A–Z・a–z、半角数字 0–9、ハイフン -、アンダースコア _、ピリオド .許可文字以外のすべて。半角・全角の空白、改行、タブ、日本語、全角英数字、@・/・\・引用符などの記号を含む。許可：employee001、user-01、user_01、user.01
禁止：user 01、ｕｓｅｒ０１、user@example.com
パスワード禁止文字を除く文字。半角・全角の英数字、日本語、記号、絵文字、半角・全角の空白を許可する。Unicodeのコードポイントで数える。日本語・絵文字も1コードポイントを1文字とし、結合文字列はコードポイントごとに数える。制御文字 U+0000–U+001F・U+007F–U+009F、行区切り U+2028、段落区切り U+2029。NULL文字、タブ、改行（LF）、復帰（CR）、削除（DEL）などを含む。許可：DailyReport123!、 secret 、日報#123
禁止：改行・タブ・NULL文字を含む値

チェック時の扱い

ログインIDは登録値と大小文字を区別して照合する。英字・数字・記号の混在を必須とはしない。JSON要求は文字列型のloginId/passwordだけを受け付け、数値/真偽値/配列/オブジェクトの暗黙変換と未知項目は400で拒否する。未指定/NULL/空文字は項目の必須チェックで判定する。

  • 入力値をそのまま検証する。前後の空白の除去、禁止文字の削除、全角・半角の変換、大文字・小文字の変換は行わない。パスワードの前後の空白も認証情報の一部として扱う。
  • 入力・貼り付けの方法によらず、送信後にAPIで同じ条件を検証する。入力不正は400と対象項目・表示文言を返し、画面は対象項目の下へその文言を表示する。画面側で同じ条件を再定義しない。
  • ログインIDの文字種エラーは「ログインIDが不正です」と表示する。
  • パスワードの禁止文字エラーは「パスワードに改行、タブなどの制御文字は使用できません。」と表示する。メッセージに入力したパスワードを含めない。

認証情報が一致しない場合はログインを成立させず、ログイン画面にエラーを表示する。

文字数の入力チェックに通っても、UTF-8で72バイトを超えるパスワードは認証できない。日本語などを含む場合は72文字以内でも該当する。画面には通常の認証失敗の案内を表示する。認証・セッション方式を参照する。

目次認証・画面遷移

認証・画面遷移

  • 社員、上長、管理者が利用する。
  • ログイン成功後は日報カレンダー・一覧へ遷移する。
  • ログイン失敗時は同じ画面に留まる。
  • 未認証では保護された画面・APIを利用できない。
  • ログアウト後はセッションを無効にする。
  • セッションの有効期限は最後の成功した認証済み業務APIアクセスから30分とする。認証状態確認・CSRF取得などの認証関連APIと、クリック・入力だけでは期限を延長しない。登録・編集画面で失効を検知した場合は未保存入力を破棄し、「セッションの有効期限が切れました。再度ログインしてください。」を表示してログイン画面へ戻る。
