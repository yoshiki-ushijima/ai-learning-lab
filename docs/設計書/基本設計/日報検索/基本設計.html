業務の流れ

  1. 社員の初期表示では本人の当月日報をカレンダー・一覧で表示する。
  2. 年月・日付範囲・社員・休日区分を指定して検索する。
  3. 一覧またはカレンダーから日報を選び、詳細を参照する。
  4. 社員本人は未登録の日付から登録へ、下書き・差戻しの登録済み日報から編集へ進む。承認待ち・承認済みは参照のみとする。
  5. 詳細からカレンダー・一覧へ戻る。

分岐・例外

  • 該当データがない場合は空の一覧を表示する。
  • 権限外・存在しない日報の内容は表示しない。
  • 不正な検索条件はエラーを表示する。

表示の共通ルール

全画面のI/O区分・表示形式・揃え方・未設定値・長文の扱いは画面表示共通ルールに従う。各画面の項目表でI/O・表示方式・揃え方を指定する。

表示制御

  • 社員は自分の当月日報を初期表示し、月カレンダーと当月日報一覧を表示する
  • 社員はカレンダーの登録可能な未登録日から登録へ進む。登録済み日報はカレンダーの表示項目または一覧の日付から詳細を開く。本人の下書き・差戻しの日報は一覧の「編集」または詳細の「編集する」から編集へ進む
  • 社員向け表示では、グループのプルダウン検索条件を表示しない
  • 上長は閲覧対象グループの日報のみ表示する
  • 管理者は全社員の日報を表示する
  • 社員のみ日報登録画面への遷移を表示する
  • 社員本人の日報のうち、下書き（DRAFT）・差戻し（REJECTED）に編集操作を表示する。承認待ち（PENDING）・承認済み（APPROVED）は参照のみとする

UI比較による表示具体化（WORK-153）

監査日時の提出・承認は左詰めの例外とする。一覧の操作列は編集可能なら「編集」、それ以外は「詳細」の1ボタンとし、日付からも詳細を開く（ユーザー回答で採用）。カレンダーの文字には内枠を付けず、未登録日は日番号を登録操作とする。操作名・キーボード・フォーカス表示を保つ。再取得はエラーからの復旧時に表示し、通常取得後は非表示。期間指定・表示月と全月表示は採用済み仕様として維持する。共通の幅・余白・980px以下の1列配置はモックに合わせ、狭幅の表は局所スクロールで文字の途中折返しを防ぐ。

初期表示と導線

  • 社員は自分の当月日報をカレンダー・一覧で確認する。
  • カレンダーの登録可能な未登録日から登録へ、登録済みの日報から詳細へ進む。本人の下書き・差戻しの日報は一覧の「編集」または詳細の「編集する」から編集へ進む。
  • 社員本人の日報のうち、下書き・差戻しに編集導線を表示する。承認待ち・承認済みは編集できない。
  • 該当データがない場合は空の一覧を表示する。

検索期間・絞り込みとカレンダー

  • 日付範囲が複数月にまたがる場合、一覧には検索対象の全期間を表示し、カレンダーには選択した月を表示する。カレンダーの表示月を切り替えても一覧の検索期間は変更しない。
  • 休日区分・承認状態等で絞り込み中は、未登録日の登録導線を表示しない。条件に合わない登録済み日を未登録として扱わない。絞り込みを解除して対象月の全件取得に成功した後に、未登録日の登録導線を表示する。

異動後の日報閲覧と社員選択肢

  • 過去の日報は、日報登録時点の所属グループを基準に閲覧権限を判定する。
  • 社員選択肢は現在の所属を基準とする。旧所属の上長の選択肢には異動済み社員を表示しない。
  • 旧所属の上長は、社員を指定しない検索から、閲覧権限を持つ旧所属在籍時の日報を参照できる。

グループ選択肢の候補と名称

  • 閲覧権限の範囲内で、現在の社員情報と過去の日報の両方からグループを集め、同じグループIDを1件にまとめる。
  • 名称は現在の社員情報を優先する。同じグループIDで名称が異なる場合は更新日時が新しい情報を使い、同時刻の場合は利用者IDの昇順で決める。
  • 現在の社員情報がなければ、最新の日報の名称を使う。同じ日付の日報が複数ある場合は日報IDの昇順で決める。
  • 名称の選択により閲覧権限の範囲を広げない。

検索条件・エラー・表示の細部

  • 検索条件の空文字、同じ条件の重複指定、未定義の条件名は入力エラーとし、入力値を自動補正しない。
  • 形式が有効な社員・グループIDの権限外指定と存在しない指定は同じ権限エラーとする。各条件が有効でも組合せに一致する日報がない場合は正常な空一覧を表示する。
  • 一覧は日付の降順、同じ日付は社員IDの昇順、さらに同じ場合は日報IDの昇順で表示する。
  • 備考の空文字は未設定として—を表示する。不正なAPI応答を正常な空一覧として扱わず、安全なエラー案内と再取得手段を表示する。
  • 入力項目に結び付かないエラーは画面全体に表示する。エラーの文言と確認順は詳細設計IO-005/IO-006に従う。
  • 社員のグループ選択肢APIの直接利用は権限エラーとする。

認証切れと遅延応答

  • 同じ画面を使っている間に届いた認証切れは、古い検索要求の応答でも即時にログイン画面へ戻す。その後に届く検索結果も表示しない。
  • 画面破棄後、または別の利用者で再ログインした後に届いた旧画面の応答は破棄し、現在の画面へ影響させない。
  • ログアウト開始前の先行要求の応答は破棄し、ログアウト処理自身の結果で画面を切り替える。

入力・取得・復帰の具体化方針

  • 年月入力は選択月の開始日・終了日へ変換し、日付範囲入力と切り替える。上長・管理者の初期期間も当月とする。
  • 無効化済みの休日区分も、過去の日報を確認するため検索・選択肢で扱う。
  • グループ変更で社員条件が合わなくなった場合は社員選択を解除する。選択肢は必要な取得がすべて成功してから適用する。
  • ログアウトで認証切れ以外の失敗が発生した場合は検索条件を保持し、一覧を再取得してから操作を再開する。
  • 一覧へ戻るときの復帰条件は、日報詳細の業務ルールを参照する。
